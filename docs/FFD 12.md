Ниже приведены форматы чеков фискализации в соответствии с ФФД 1.2 (формат фискальных документов).

Чек описывается как объект JSON. Длина — не более 29999 символов.

### Формат 1.2 чека прихода/возврата прихода

```jsonc
{
    // Контакты плательщика для отправки текста фискального чека.
    // Этот блок может отсутствовать целиком,
    // или в нем могут отсутствовать какие-то элементы.
    customer: {
        phone: "номер телефона плательщика",
        email: "адрес электронной почты плательщика",
        id: "идентификатор плательщика, присвоенный мерчантом",
        // дополнительная информация о покупателе (все параметры опциональные)
        name: "Название покупателя",
        inn: "ИНН покупателя",
        birthday: "дата рождения покупателя (клиента)",
        citizenship: "гражданство",
        doccode: "код вида документа, удостоверяющего личность",
        docdata: "данные документа, удостоверяющего личность",
        address: "адрес покупателя (клиента)"
    },
    // Опциональный блок данных кассира
    cashier:{
        name: "Ф. И. О. кассира",
        inn: "ИНН кассира"
    },
    taxmode: "значение системы налогообложения",
    // Массив товарных позиций в чеке.
    // Должен содержать хотя бы один элемент.
    // Общая сумма по всем позициям должна быть равна общей сумме чека
    lines: [
        // Описание позиции.
        // Все поля обязательны и не могут быть пустыми,
        // поле qty не может иметь нулевое значение.
       {
            name: "наименование позиции",
            price: "цена за единицу измерения",
            qty: "количество",
            //дробное количество доступно только для товаров с маркировкой
            qtypart: {
                numerator: "числитель",
                denominator: "знаменатель"
            },
            //если не передана мера количества предмета расчета, по умолчанию подставим 0 - штуки
            unit: "мера количества предмета расчета"
            sum: "сумма",
            vat: "значение ставки НДС",
            payattr: "Признак способа расчета",
            lineattr: "Признак предмета расчета",
            //Опциональный блок - дополнительные сведения о продукте
            product:{
                kt: "Код маркировки или штрих-код",
                exc: "Акциз",
                coc: "Код страны происхождения товара",
                ncd: "Номер таможенной декларации"
            },
            //Опциональный блок данных агента
            agent:{
                agentattr: "Признак агента",
                agentphone: "Телефон платежного агента",
                accopphone: "Телефон оператора по приему платежей",
                opphone: "Телефон оператора перевода",
                opname: "наименование оператора перевода",
                opinn: "ИНН оператора перевода",
                opaddress: "адрес оператора перевода",
                operation: "операция платежного агента",
                suppliername: "наименование поставщика",
                supplierinn: "ИНН поставщика",
                supplierphone: "телефон поставщика, строго в формате \"+7XXXXXXXXXX\" или \"+7-XXX-XXX-XX-XX\"",
            }
        },
        …
    ],
    // Опциональный параметр с произвольными данными от мерчанта.
    // Транслируется в неизменном виде во всех фискализированных
    // чеках, созданных в процессе оплаты по данному чеку.
    // Формат: json-объект произвольной внутренней структуры
    optional: { “данные мерчанта” },
    senderemail: "адрес электронной почты отправителя чека",
    // Дополнительные параметры платежа.
    // Этот блок может отсутствовать целиком,
    // или в нем могут отсутствовать какие-то элементы.
    params: {
        //в параметре place можно указать url одного из сайтов,
        //перечисленных в Личном кабинете налоговой мерчанта.
        place: "место расчета"
    },
        //Обязательный блок информации об оплате дополнительными платежными средствами
    payments: [
       {
        //вид платежного средства:
        // 1 – Оплата банковской картой
        // 2 – Оплата электронной валютой
        // 3 – Оплата с помощью кредитной организации
        // 4 – Оплата дополнительным платежным средством
        kind: "вид платежного средства",
        //параметр тип дополнительного платежного средства:
        // 1 - Подарочные карты Мерчанта
        // 2 - Бонусы-авансы Мерчанта
        // 3 - Прямой аванс Мерчанта
        // 4 - Использование авансов/билетов
        // 5 - Платеж через кредитную организацию (банкомат)
        // 6 - Платеж через кредитную организацию (online)
        // 7 - Безналичное перечисление через банк
        // 8 - Оплата «онлайн кредитом»
        // 9 - Оплата по СМС
        // 10 - Эквайринг внешний
        // 11 - Платеж через терминал электронными
        // 12 - Платеж через терминал наличными
        // 13 - Наличные
        // 14 - Продажа в кредит
        // 15 - Встречное предоставление
        // 16 - Сертификат Uniteller
        type: "тип платежного средства",
        // опциональный параметр – идентификатор платежного средства
        // например, номер бонусной карты,
        // номер подарочного сертификата, номер лицевого счета
        id: "идентификатор платежного средства",
        amount: "сумма оплаты платежным средством",
       },
        …
    ],
    total: "итоговая сумма чека",
}
```
Примечание:

1. Внимание! Так как фискальный накопитель хранит данные в кодировке CP866, а передаются они в кодировке UTF-8, то в поле “name” («Наименование позиции») можно указывать только те Unicode-символы, для которых есть соответствие в CP866.
2. Длина поля “name” («Наименование позиции») не должна превышать 128 символов.
3. Формат полей:
   * customer.name — строка 0–243 символов включительно;  
   * customer.inn — 10-12 цифр или пусто;  
   * customer.birthday — строка 10 символов в формате ДД.ММ.ГГГГ.  
   * customer.citizenship — строка 3 символов, если код страны имеет длину меньше 3 цифр, то слева добавляются нули.  
   * customer.doccode — строка 2 символов. Возможные значения указаны в Приложении 13.  
   * customer.docdata — строка до 64 символов.  
   * customer.address — строка до 256 символов.  
   * cashier.name — строка 0–240 символов включительно;  
   * cashier.inn — 12 цифр или пусто.  
   * kt — может быть передан в 2 вариантах:
     * строка до 256 символов;  
     * строка до 512 символов в HEX-формате, начинающаяся с 0x (признак 16-ричного формата), например:
       ```text
       "kt":"0x444D02A3357919913962546563775844562e705a46"
       ```
       (этот вариант нужен, когда нельзя запаковать в json строку, содержащую символы, несоответствующие UTF-8).  
     * Если на упаковке присутствует как код маркировки, так и штрих-код, то необходимо передать штрих-код. Если в коде маркировки встречается символ FNC1, то он должен передаваться как байт с кодом 0x1d.
